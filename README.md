# GREEN HOLDING LIVE COMMAND CENTER

Full-stack web app for managing and monitoring company TikTok livestream operations in real-time / near-real-time. It is usable today in **MOCK MODE** and is structured so TikTok credentials can be plugged in later without rewriting the dashboard or database.

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/haihang1234567/green-holding-live-command-center)

## Included

- FastAPI backend + JWT authentication
- PostgreSQL database
- React/Vite responsive Command Center
- WebSocket dashboard refresh
- 2 TikTok channels + 4 seeded teams: Hoàng Ảnh, Lam Dần, Hạo Ưng, Long Tài
- Admin vs Team access control
- LIVE session lifecycle and manual fallback
- GMV / Orders / AOV / Ads / Ads% / ROAS / GMV-hour KPIs
- Top SKU and team ranking
- Refund/cancel snapshots: T+0, 1H, 3H, 6H, 12H, 24H, 48H, FINAL
- Threshold alerts: LIVE start/end, GMV velocity, Ads/GMV, Refund, integration errors
- Mock simulator: start/stop, orders, GMV, ads, cancel/refund
- TikTok Shop adapter + signing + token refresh + orders/returns + webhook receiver
- TikTok Marketing API report adapter
- Optional generic LIVE status endpoint adapter
- Channel/Shop/Advertiser mapping UI
- User management UI
- Auto team mapping per channel / shift
- Filterable reports + Excel/PDF export
- Docker Compose local deployment
- Render Blueprint one-click deployment

## Deploy online on Render

The repository includes `render.yaml` and a production root `Dockerfile`. Render builds the React frontend, serves it from FastAPI on the same HTTPS origin, and provisions PostgreSQL automatically.

1. Click **Deploy to Render** above.
2. Sign in to Render and connect GitHub if requested.
3. Review the Blueprint resources.
4. Enter a strong value for `ADMIN_PASSWORD` when Render prompts for it.
5. Click **Apply**.
6. Wait for the database and web service to become Live, then open the generated `onrender.com` URL.

The initial deployment uses:

- `DATA_PROVIDER=MOCK`
- `LIVE_STATUS_PROVIDER=MOCK`
- Singapore region
- Render Free web service and Free PostgreSQL for initial testing

### Render Free plan warning

The free deployment is intended for demo/testing. A free Render web service can idle-suspend, and free Render PostgreSQL expires after its free retention period. For continuous TikTok polling, scheduled refund snapshots, and production company data, upgrade the web service and PostgreSQL to non-free plans before going live.

## Start locally

```bash
cp .env.example .env
docker compose up --build -d
```

Open `http://localhost:8080`.

- Admin: `admin` / `admin123`
- Team demo: `hoanganh`, `lamdan`, `haoung`, `longtai` / `team123`

## When TikTok approves the APIs

For local Docker, edit `.env`. For Render, open the web service's **Environment** page and add/update the same variables:

```env
DATA_PROVIDER=TIKTOK
LIVE_STATUS_PROVIDER=MANUAL
TIKTOK_SHOP_APP_KEY=...
TIKTOK_SHOP_APP_SECRET=...
TIKTOK_SHOP_ACCESS_TOKEN=...
TIKTOK_SHOP_REFRESH_TOKEN=...
TIKTOK_ADS_APP_ID=...
TIKTOK_ADS_SECRET=...
TIKTOK_ADS_ACCESS_TOKEN=...
```

For two TikTok Shops, use the JSON token maps documented in `.env.example`.

In the admin UI:

1. **Kênh TikTok** → enter `shop_cipher`, Shop ID and `advertiser_id` for each of the two channels.
2. **Cấu hình API** → test Shop / Ads and configure channel+shift → team mapping.
3. If there is no approved LIVE status source, keep `LIVE_STATUS_PROVIDER=MANUAL` and use **LIVE hiện tại** to start/stop sessions. Real Shop/Ads data still syncs into those sessions.

See `docs/TIKTOK_INTEGRATION.md` for the full checklist.

## Security

- Never commit `.env`.
- App secrets/tokens are backend-only.
- Change the admin password before production.
- `SECRET_KEY` is randomly generated by the Render Blueprint.
- The repository should be private before real credentials or company-sensitive implementation details are added.
